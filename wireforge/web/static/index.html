How it works

Three steps, all of them checked.

  1. Trace it
  2. Forge it
  3. Prove it

Trace it

The forge agent uses the site in a real browser, the way a person would: search, pick, add. Every XHR and fetch the page fires is recorded with its headers, body and response, so the agent reads the site's own backend instead of guessing from HTML.

wireforge/browser.py · BrowserSession._on_response

Forge it

It proves each endpoint with direct HTTP calls, changing one parameter at a time, then writes the action and its return schema. Every emit is executed on the spot and schema-checked, so a broken action is fixed before anyone else sees it.

wireforge/forge.py · Forge.emit

Prove it

A separate verifier, in a fresh browser with no access to the forge's reasoning, runs the action with its own inputs and compares names, prices and counts with the rendered page. For add-to-cart it opens the cart with the action's own session. Rejected actions go back for repair.

wireforge/verifier.py · Verifier.submit

Built around proof, not plausibility.

Evidence before code

The agent writes nothing until it has watched the endpoint answer in the browser and answered again to its own direct call with a changed parameter.

Emitted means executed

Every emit runs in a separate process and is validated against a strict return schema. The agent cannot finish on an action that did not pass.

Verified means compared

At least two runs, at least three values checked against the page. An unexplained mismatch turns a pass into a fail, whatever the verifier wrote.

Two agents, one direction

The forge cannot judge its own work. The verifier cannot edit code. Its report is the only thing that flows back.

Stops at the cart

Checkout, payment and order endpoints are refused in the probe tool and in the action harness itself, so a write action can add to a cart and read it back, and nothing more.

The demo ladder

Four levels, one pipeline.

Level 1

One endpoint

BMTC routes, VTU results. Input in, JSON out.

Level 2

Chained calls

RedBus, IRCTC. Ids from one response feed the next request.

Level 3

Hidden state

Myntra, MakeMyTrip. Pagination, cursors and session-bound APIs.

Level 4

Write actions

Snitch, boAt, Mokobara. Resolve the size variant, add to cart, prove it in the cart.

None of these sites were in the Wire catalog when we checked it on 26 September 2026.

    Safety

    What it will never do.

    No checkout, no payment, no orders

    Paths containing checkout, payment, /pay, place-order or purchase are refused by the probe tool and by the harness that runs every action. Write actions end at the cart.

    config.BLOCKED_PATH_WORDS · probe.blocked · harness._guard

    No passwords

    Demo sites are public or guest-cart only. Actions may not hard-code cookies or tokens copied from the browser; they fetch what they need at run time.

    forge.SYSTEM

    Starting a run needs the passcode

    Reading the board, actions and results is public. Starting a run drives a real browser and spends credits, so it needs the passcode from the submission, and only one run happens at a time.

    web/server.py · start_run

    Untrusted pages stay data

    Everything a website returns is shown as text on this board, never rendered as HTML, and it never changes what the pipeline is allowed to do.
